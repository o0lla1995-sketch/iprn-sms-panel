5.8 الملفات — Profiles WHOLESALE / WSALE

الملفات هي «أنواع الترافيك» التي تحملها وكيف يجب التعامل معها. ملفاتك الحالية تُعرض بجدول: الملف، الرمز (يُرسل كـ service_type في SMPP)، الصلاحية، الأولوية، افتراضي أم لا، ومن أسندته (المشغل). وتحتها نموذج «اقتراح ملف» لأقتراح نوع ترافيك تحمله: اسمه (مثال العنصر النائب: BANKING-OTP)، صلاحيته بالدقائق (افتراضي 1440)، أولويته (Normal / High)، أرضية DLR بالنسبة المئوية (افتراضي 60%)، وخيار بحث HLR/MNP. وينص التقديم: «يقترح المشغل مراجعته وقد يعدله، وعند الموافقة يُسند إليك».

حالة حسابك: ملف واحد: WHOLESALE برمز WSALE — صلاحية يوم واحد، أولوية NORMAL، الملف الافتراضي للحساب، مُسند من المشغل. ولا اقتراحات: «No proposals yet».

5.10 الموصلات الواردة — Inbound Connectors منك ← المنصة

أغنى صفحات اللوحة محتوى، وقد فُصّلت بنيتها في القسم §04. وهي تجمع خمس كتل متتالية: روابط SMPP (ثوابت المنصة، جدول روابطك بعمودي الحالة والاتصال مع أدوات التعطيل والحذف، ونموذج إضافة ربط جديد)؛ ثم HTTP API (المفتاح، نقطة النهاية، صيغة الطلب، صندوق التجربة التفاعلي بأزرار cURL/Node.js/Python وزر «Try it (dry-run)» الذي يسعّر الرسالة دون إرسالها)؛ ثم قائمة سماح IP لواجهة API؛ ثم خطاف الوارد (MO Webhook) لنسخ المورد؛ وأخيرًا أسماء المرسل (Sender IDs): «مرسلات أبجدية رقمية (كاسم علامة تجارية). بعض الأسواق تتطلب تسجيلًا قبل الاستخدام — اطلب هنا ويوافق مشغل». تُسجَّل بطلب يحمل الاسم والوجهة الاختيارية.

حالة حسابك: ربط واحد (system_id «450»، نشط، الاتصال «Connecting») · لا أسماء مرسل مسجلة: «No sender IDs yet» · الخطاف معطّل (لا عنوان مضبوط) · مفتاح API نشط قابل للتدوير · قائمة سماح IP فارغة (السماح لأي مصدر).

5.11 الفوترة — Billing دورات وسحب

تنظيم دورة أموالك، بأربع كتل. الإعدادات: اختيار دورة الفوترة بين أسبوعية (Weekly Factoring بفترة 7/7 أيام — بخصم 30%) وشهرية افتراضية (30/30 — بلا خصم)، مع ضمان «الفاتورة القادمة تبدأ حيث انتهت سابقتها، فلا يوم يُفوتر مرتين ولا يسقط»؛ ثم بيانات السحب المالي (حساب/IBAN/SWIFT، محفظة…). تنبيهات الاستخدام: عتبة تختارها (عدد رسائل، أو قطع Segments، أو مبلغ مفوتر بالدولار) ودورية (يومي/شهري/سنوي/مرة واحدة)، تصل إلى لوحتك وبريدك، مع قاعدة: «المفوتر لا يحسب إلا ما فُوتر فعلاً — الرسالة المنتظرة تسليمها ليست بعد مفترة». المدفوعات (Payouts): «الحد الأدنى للدفع 200.00 دولار». الفواتير: تُولَّد لكل دورة مقفلة بأعمدة الرقم/الفترة/النوع/الرسائل/الإجمالي/الاتجاه/المسوى/المتبقي، والنقر على فاتورة يفتح بنودها. وأخيرًا قيود الحساب: «الأموال التي حركناها يدويًا — تسويات وتصحيحات وتسويات؛ رسائلك ليست هنا بل في فواتيرك».

حالة حسابك: الرصيد 0.0000 و«Below the minimum, so no payout is due yet» · لا فواتير: «No invoices yet» · لا قيود يدوية: «Nothing has been recorded by hand on this account» · الفاتورة القادمة: 10/1/2026 – 11/1/2026 · بيانات السحب غير معبأة.

5.12 الدعم — Support مساعد + تذاكر

تبويبان: المساعد — مساعد ذكي مطلع على بياناتك يجيب عن الأرقام والموصلات والرسائل والتعرفات والفوترة، ويستطيع فتح تذكرة بشرية عند الحاجة؛ وقد استُخدم فعليًا خلال هذه الدراسة مرتين وخرج بتوصيف دقيق للمنصة ثم بتشخيص عائقَي حسابك (راجع §02 و§07). وتذاكري: جدول تذاكر الدعم (الرقم، الموضوع، الحالة، تاريخ الفتح) مع زر تذكرة جديدة.

حالة حسابك: «No tickets yet» — لم تُفتح أي تذكرة دعم من قبل؛ والمساعد متاح فورًا دون تذكرة.
خلاصة الجولة: الصفحات الاثنتا عشرة ليست أقسامًا منفصلة بل مسارًا واحدًا: تمتد الأرقام (Numbers) لتولّد ترافيكًا يصلك عبر موصل صادر (Outbound Connectors) ويُسجل رسائلًا (Outbound Messages) بتسوية من أسعار التسوية (Settlement Rates) تُقفل في فواتير (Billing) وتُسحب مدفوعاتها، بينما قائمة الوصول (Access List) ترشدك إلى حيث الترافيك، والموصلات الواردة (Inbound Connectors) تمنحك قناة الاتصال المعاكسة وHTTP API، والدعم والمساعد يغطيان ما عدا ذلك. حسابك «مسلّح هيكليًا» في كل صفحة لكنه بلا ذخيرة تشغيلية في أيٍّ منها — وهذا موضوع القسم التالي في محور الإرسال ثم تحليل الحالة.
